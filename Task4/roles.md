# Задание 4. Роли доступа к Kubernetes

Предлагаемая модель учитывает четыре домена PropDevelopment: продажи, ЖКУ, финансы и обработка данных. Доступ выдаётся группам сотрудников в пределах их зоны ответственности.

| Роль                                            | Права роли                                                                                                                                                                                                                                                                                                                                                | Группы пользователей                                                                                                                |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `resource-reader` — просмотр ресурсов           | В назначенном namespace: `get`, `list`, `watch` для `pods`, `services`, `endpoints`, `configmaps`, `persistentvolumeclaims`, `events`, `deployments`, `replicasets`, `statefulsets`, `jobs`, `cronjobs`, `ingresses`, `networkpolicies`. Без чтения Secrets, изменения ресурсов и выполнения команд в контейнерах.                                        | Разработчики и инженеры поддержки соответствующего домена: `<domain>-readers`.                                                      |
| `namespace-configurator` — настройка приложений | В назначенном namespace: права просмотра перечисленных выше ресурсов; дополнительно `create`, `update`, `patch`, `delete` для `pods`, `services`, `configmaps`, `persistentvolumeclaims`, `deployments`, `statefulsets`, `jobs`, `cronjobs`, `ingresses`. Без прямого доступа к Secrets, изменения RBAC, NetworkPolicy, квот и ресурсов других namespace. | DevOps-инженеры и инженеры по эксплуатации соответствующего домена: `<domain>-configurators`.                                       |
| `secret-manager` — управление секретами         | В назначенном namespace: `get`, `list`, `watch`, `create`, `update`, `patch`, `delete` для `secrets`. Работа с учётными данными БД, ключами и токенами интеграций.                                                                                                                                                                                        | Выделенные инженеры, отвечающие за секреты своего домена: `<domain>-secret-managers`. Назначение согласуется со специалистом по ИБ. |
| `cluster-admin` — администрирование кластера    | Полный доступ к ресурсам кластера: управление namespace, узлами, сетевыми политиками, квотами, ролями и их назначениями. Включает доступ к Secrets во всех namespace. Используется для администрирования и аварийных работ.                                                                                                                               | Ограниченная группа администраторов инфраструктуры: `platform-admins`.                                                              |

Для первых трёх ролей используются одинаковые наборы полномочий, но отдельные RoleBinding в каждом namespace. `cluster-admin` назначается через ClusterRoleBinding. Права разных назначенных ролей складываются.

## Разделение по доменам

| Namespace       | Сервисы / зона ответственности                                             | Группы пользователей                                                        |
| --------------- | -------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `sales`         | Витрина продаж, онлайн-туры, сделки, клиентская CRM и каталог недвижимости | `sales-readers`, `sales-configurators`, `sales-secret-managers`             |
| `housing`       | Сервисы ЖКУ, `tenant-core-app`, CRM собственников                          | `housing-readers`, `housing-configurators`, `housing-secret-managers`       |
| `finance`       | Финансовый учёт и его компоненты, размещённые в Kubernetes                 | `finance-readers`, `finance-configurators`, `finance-secret-managers`       |
| `data`          | Компоненты обработки данных, BI и отчётности, размещённые в Kubernetes     | `data-readers`, `data-configurators`, `data-secret-managers`                |
| `smarthome`     | `smarthome-service` и `smarthome-db` из Task3                              | `smarthome-readers`, `smarthome-configurators`, `smarthome-secret-managers` |
| `smarthome-dmz` | Внешний API-шлюз интеграции умного дома                                    | `smarthome-readers`, `smarthome-configurators`, `smarthome-secret-managers` |

Умный дом относится к домену ЖКУ, но доступ к его компонентам выделен отдельно для сотрудников, сопровождающих интеграцию. Отдельный namespace шлюза обозначает зону управления. Сетевую изоляцию DMZ нужно дополнительно обеспечивать сетевыми правилами. Доступ к одному домену не даёт доступа к другим. Менеджерам операционных команд, владельцам продуктов, клиентам, собственникам и партнёрам доступ к Kubernetes не требуется: они работают через приложения и API.
